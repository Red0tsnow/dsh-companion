# 迁移、升级和回滚

迁移工具读取旧数据，复制到指定的新角色目录，保留源文件。请先预览，再决定是否执行。

```powershell
node tools/migrate.mjs --source "<旧DSH数据目录>" --target "<新角色数据目录>"
node tools/migrate.mjs --source "<旧DSH数据目录>" --target "<新角色数据目录>" --apply
```

不提供 `--source` 时按用户旧 `.dsh` 目录解析。不提供 `--target` 时按插件数据根目录解析。目标可以是旧 DSH 根目录下新的 `companion` 子目录；工具按精确白名单枚举，不递归复制整个旧目录。源和目标不能相同，目标也不能包含源；迁移拒绝符号链接和 junction，避免越出选定目录。为避免和初始化空文件冲突，建议先迁入一个独立空目录，再用 `DSH_COMPANION_HOME` 指向它启动插件。已有目标文件会保留，并在报告中显示跳过，不会覆盖。

## 会复制哪些内容

| 旧内容 | 新位置与处理 |
|---|---|
| 人设、便签、长期记忆、印象、手札、睡前一句 | `workspace` 中的对应文件 |
| 公共日记、私人日记 | `workspace/diary.md`、`workspace/diary-private.md` |
| 旧操作规则 | 作为迁移规则保留，需审阅，不能自动信任旧脚本路径 |
| Minecraft 目标 | `runtime/mc/goal.md` |
| 自有技能 | `runtime/mc/skills`，检查其中的绝对路径和依赖 |
| 闹钟 | `schedules`，默认停用，检查路径、时间和目标后启用 |

不复制旧会话日志、Minecraft 存档或服务端 jar，不替换正在运行的身体，不复制旧插件实现、`node_modules`、自启动入口或全局消息钩子。新的身体由插件模板初始化，角色身份通过迁入的人设、记忆和文字延续。

## 凭据

只有添加 `--credentials` 才复制支持的账号字段。目标已有凭据保留；不记录凭据值到报告。小黑盒自备 CLI 是否使用新凭据视图，取决于它是否遵守 [外部工具契约](usage.md#小黑盒用户自备工具)。

迁移结果写入目标目录的 `migration-report.json`，用于核对复制、跳过和失败的文件。预览不会创建目标目录或报告。

## 升级

1. 在面板中结束需要停止的世界操作，确认任务已收尾。
2. 备份完整角色数据目录，保留当前可用版本的 `.tgz`。
3. 安装新版插件并重启 DSH profile。
4. 核对人设、会话身份、文字及通道配置，运行依赖和连接检测。

新版模板不会静默覆盖 `runtime/mc/mc-daemon.mjs` 的自改内容。若需采纳模板变更，先比较差异、备份并试用，再通过身体工作流应用。

## 卸载与回滚

```powershell
dsh plugin --profile desktop remove dsh-companion
```

卸载后重启该 profile。插件释放自己的路由、WS 连接、监听器和计时器，数据目录保留。正在运行的 Minecraft 世界请先显式关闭。

回滚时安装保留的旧版本包并重启。如新版已经改变数据，先保留当前数据副本，再恢复自己的已知可用备份。迁移工具不删除原部署，因此可以回到原部署；请避免同时启用两个会处理同一 QQ 账号或同一世界的自动入口。
