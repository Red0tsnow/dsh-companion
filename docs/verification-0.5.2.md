# 0.5.2：皮肤交付记录

2026-10-26，补齐用户客户端截图后，开放固定的 Paper 1.21.8 build 60 与 SkinsRestorer 15.12.6。其他版本继续使用原版。

## 完成内容

- 将皮肤截图及 SHA-256 绑定到固定组件记录；截图在 [皮肤验收记录](skin-spike.md)。
- 皮肤操作走原世界 supervisor 的 stdin。命令通过世界锁串行，核对实例、启动标识、PID 与创建时间；不另起 Java、不强杀。CLI 为 `world.mjs command "<白名单命令>"`。
- 命令白名单只有两条：`sr createcustom companion_skin <https 图片>`、`skin set companion_skin <角色名>`；命令串禁止换行与控制字符，URL 只收 https，角色名限定 `[A-Za-z0-9_]{1,16}`。
- 固定皮肤名 `companion_skin`，玩家名来自配置，先 `sr createcustom`，再 `skin set companion_skin <玩家名>`。
- 图片预检查、服务端获取失败、插件未加载、角色离线、命令超时分别报错；仅明确回执可显示成功。超时后暂停本次世界实例的后续皮肤命令，需正常重启，防止旧异步回执被当作新命令成功。
- 面板提供皮肤输入、保留失败后的输入、版本提示与中英文文案。切换到不支持的游戏版本时重置为原版。
- Paper 与 Modrinth 的响应/停滞超时延长为 120 秒，网络失败重试一次；错误含来源与阶段。原有 HTTPS、逐跳白名单、尺寸、哈希、临时文件及原子落盘保护保留。
- 新建 Paper 的配置使用常规进服路径，避开可选 Paper 监听造成的首次登录阻塞；已有插件配置保留。

## 顺手修的一个测试缺陷

`tests/patch051.test.mjs` 里「从 0.5.0 的 Paper 目录回退到原版」这条，以前默认 25565 没人监听；
只要本机正在世界里玩，它就会假失败（报「请先关闭当前世界」）。现在改成临时监听一个端口再关掉，
取一个确定空闲的端口写进 fixture，和执行测试的机器状态无关。
